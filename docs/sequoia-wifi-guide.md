# 8265 网卡在 macOS 15 上能不能用 Wi-Fi

写给不熟悉技术细节的人。看完这一篇，你应该能自己判断该怎么做。

---

## 先说结论

你的 Intel 8265 网卡，**在 macOS 15 上可以用** —— 但不是开箱即用，要先做适配。

目前的状态（2026-10-20，本机实测）：

| 阶段 | 状态 |
|---|---|
| 驱动加载 | ✅ 已解决 |
| 硬件启动、固件对话、校准数据回放 | ✅ 已解决 |

## 一、发生了什么

### 把 Wi-Fi 想成一个餐厅

- **菜单栏、系统设置里的 Wi-Fi 开关** = 前台，你在这里点"连哪个 Wi-Fi"
- **macOS 自带的 Wi-Fi 驱动** = 后厨，负责真正收发信号
- **AirportItlwm 这类第三方驱动** = 外包供应商

你点一下 Wi-Fi，外包供应商就跑去后厨下单取货。后厨和供应商之间有一套约定：怎么喊单、从哪个门交货、厨房设备怎么用。

这套约定，在代码里有个名字，英文的，叫 `IO80211Family`。

### 老规矩能用，新规矩不行了

- **macOS 14（Sonoma）及更早**：后厨是老后厨，规矩没变。外包供应商按老规矩下单，取货成功。
- **macOS 15（Sequoia）**：苹果把后厨拆了重建。

后厨挪了位置，规矩也改了。更麻烦的是——**苹果没有告诉外界新规矩是什么。**

### 这就是问题所在

系统每次要装一个第三方驱动，会先做一次检查：

> 你这个供应商需要的那些"设备"，新后厨还配得上吗？

在 macOS 14 上，全配得上。在 macOS 15 上，有一批设备**换了型号，还有的直接取消了**。

配不上的结果就是系统拒绝安装，并且报错。错误信息大意是：

> 你要的这个设备，系统里找不到。

### 那为什么官方一直不修

两个原因：

1. **苹果不公开新规矩**，也不给第三方正式的接入方式。相当于让外面的人自己摸黑进厨房研究。维护者明确说过这基本等于破解，而且没有测试机器。
2. **没有测试条件**。第三方驱动必须在真实机器上反复试，光看代码不行。

所以从 2024 年 macOS 15 发布到现在，官方版本**一直没支持**，这个情况已经持续两年多了。

## 二、有个第三方版本声称可以

GitHub 上有个个人做的分支（`AirportItlwm-Sequoia`），声称在 macOS 15 上能跑。

### 它是怎么做到的

说白了就两步：

**第一步，重新做一张"设备清单"。**
原来那张是按老后厨画的。现在按新后厨重新画一遍，把换了型号的设备改成新型号。

**第二步，缺的那个设备，自己造一个。**
清单上有个设备新后厨取消了，既然取消了就自己做一个顶上，这样系统检查时就不会卡住。

再往深处，它还重写了下单流程，因为苹果把关键环节挪到了新地方，老路子走不通了。

### 为什么它能做成，官方做不成

**不是因为它的人更厉害，是它管的事小得多。**

它只支持：

- **一张网卡**（AX210）
- **一个系统版本**（精确到某个具体的系统构建号）
- **一种加密方式**（WPA2）

就管这么点范围，人力一个个试过去是能试出来的。

要覆盖几十种网卡、十几个系统版本，还要保证以后一直能用——那完全是另一个量级的工作。

### ⚠️ 2026-10-20 更新：这个版本的实际情况比想象的乐观

下面是当时的判断。**实测之后需要修正两处**：

1. **"只认 7000 系列"这道门是可以拆的** —— 那只是代码里的几行检查，不是固件层面的限制。实测证明 8000 系列的固件（你的 8265 是固件 36）**完整接受**作者写的那套对话流程，连校准数据的回放格式都不用改。
2. **"需要逆向移植整个命令传输层"这个判断过重了** —— 命令传输层在 8000 系列上**原生就能用**。真正要改的只有：几处系列检查、扫描请求要改走固件偏好的格式、一张段号对照表、两个信道细节。

**⇒ 结论从"用不了，不值得折腾"变成"**已经跑通了，扫得到、连得上、能上网**"。★★**
**★ 真正的分水岭不是"只认 7000 系列"这道门，而是**扫描请求的命令格式属于家族边界** —— 作者自建的那套扫描请求用的是 7000 家族的命令，8000 家族的固件收到就复位，改成固件自己要的格式就好了。★★**

### 必须知道的实话

**1. 这是 AI 辅助开发的**
项目作者在自己的说明里写清楚了，这个分支是用 AI（OpenAI Codex）辅助完成的。他自己一个人做了范围决策，然后在**他自己那一台机器**上测试。

**2. 你的 8265 原本不在支持范围内**（但已经被适配掉了）

它作者测试用的是 AX210 网卡。你的 8265 原本卡在两处：

- **允许名单**：8265 的硬件 ID 是 `0x24FD`，不在这个版本的名单里。原样装上去，驱动会静默不加载。
- **更关键的一条**：这个版本内部给 Intel 老一代 Wi-Fi 写的代码，只认 **7000 系列**（7265 / 3165 / 3168 / 3160）。而 **8265 属于 8000 系列**。代码里有一句明确的检查，不是 7000 系列就直接拒绝 —— 扫描被拒、连接也被拒。

**这两条现在已经解决了**（本机实测）：名单已放开，系列检查已改为"7000 / 8000 都放行，9000 继续拒绝"。**驱动能加载、能启动、系统里能看到 Wi-Fi 端口。**

不过**别把"作者的支持范围"和"我们的适配成果"混为一谈** —— 下面第 5 点说的那些坑，作者在 8265 上一个都没测过。

> 顺带一提：如果你的卡是 Intel **7265 或 3165**（属于 7000 系列），情况完全反过来 —— 那个版本的底层代码就是为它们写的，只需要放开名单，很可能开箱可用。
> 如果换成 **AX210 / AX211**，那是作者亲手验证过的组合，风险最低。

**3. 缺的功能不少**
明确不支持的：

- WPA3 加密
- 6 GHz 频段
- 隔空投屏、AirDrop
- 手机热点

**4. 有些情况没测试过**
作者自己列出来的"还没验证"清单：

- 睡眠唤醒后能不能正常
- Wi-Fi 断了能不能自动恢复
- 连接时间长了会不会出问题
- 换密码（换密钥）会不会断

这些都是日常使用会遇到的情况，但确实没测。

**5. 系统一更新就可能失效**
下一节详细说，这是最关键的坑。

## 三、你必须先做的一件事

这个版本**认死理地只认某一个系统版本**，认得极其严格——比对着身份证号验明正身还严。

系统只要更新过哪怕一次（安全更新也算），就会对不上，然后驱动**静默失效**：

> 不报错，不提示，只是 Wi-Fi 图标不出来。

所以**在动手之前**，请先查你机器的系统版本。

### 怎么查

打开「应用程序 → 实用工具 → 终端」，复制粘贴这一行，回车：

```
uname -v
```

会输出一行字，类似这样：

```
Darwin Kernel Version 24.6.0: Sun Aug 23 20:30:56 PDT 2026; root:xnu-11417.140.69.712.69~1/RELEASE_X86_64
```

这个版本要求**一字不差**地对上：

```
Darwin Kernel Version 24.6.0: Sun Aug 23 20:30:56 PDT 2026; root:xnu-11417.140.69.712.69~1/RELEASE_X86_64
```

### 怎么看结果

把 `uname -v` 输出的那行，和上面那行仔细对比：

| 对比结果 | 说明 |
|---|---|
| 一模一样 | 可以往下走 |
| 开头是 `24.6.0` 但后面的数字不一样 | 用不了。想用得自己改代码重新编译 |
| 开头不是 `24.6.0`（比如 `24.4`、`24.7`） | 用不了 |
| 完全不知道什么意思 | 把结果发给懂技术的人看 |

### 一个需要注意的地方

这个项目的说明文档里写它测试的环境是 **macOS 15.8**，但代码里写死的却是对应 **macOS 15.6** 的版本号。**这两处对不上。**

以实际代码为准。也就是说，这个项目的文档记录不够严谨，**所以你一定要自己查，不要相信文档里写的版本号。**

## 四、你有哪些选择

### 选项 A：留在 macOS 14（推荐）

**如果你想要稳定，这是最省心的路。**

- 你的 8265 在 macOS 14 上有官方支持，很成熟
- 不需要折腾任何东西
- 代价：暂时用不了 macOS 15

8265 是 2015 年的老网卡了。如果你这台机器用着顺手，停在 macOS 14 完全没问题，很多老笔记本都这样。

### 选项 B：用第三方版本试 macOS 15

**如果你就是想在 macOS 15 上用原生 Wi-Fi。**

前提：第三节的版本检查必须通过。

如果通过，你需要知道：

- **原版对 8265 是不工作的**（需要按第三节的思路适配；本仓库的适配记录见 [`sequoia-8265-port.md`](sequoia-8265-port.md)）
- 缺不少功能（隔空投屏、WPA3 都没有）
- 系统更新后很可能要重新弄一遍
- 有些日常场景没验证过（睡眠唤醒、断线恢复）

**★ 一条硬性要求：驱动内核版本必须逐字节匹配。★**
这个 fork 在加载前会核对系统内核版本串（例如 `Darwin Kernel Version 24.6.0: ... xnu-11417.140.69.712.69~1`）。**差一个字符就静默不加载**，而且没有任何提示。系统安全更新后必须重新编译。

**★ 另一条：必须加 `itlwm_assoc_scan=1`。★**
不加这个，系统设置里的 Wi-Fi 列表**只会显示最后一个信道的网络** —— 因为连上之后系统请求扫描会被驱动拒掉，列表就冻结了。实测加上之后：104 次请求全部执行、零拒绝、列表里能看到全部 86 个附近网络。

完整的 boot-args（实测可用）：

```
darkwake=0 ps2kbdonly=1 -wegnoegpu itlwm_native=1 itlwm_bsd_owner=skywalk itlwm_assoc_scan=1
```

**★ 如果你装的是不带诊断的发布版：★**
发布版不往系统注册表里写任何诊断属性，也不在系统日志里打任何调试行 —— 出了问题会**更难查**（看不到属性就不知道卡在哪一步）。
**★ 所以：日常用发布版，出问题时换回带诊断的开发版。两者是同一份源码，只差一个编译开关。★★**

**风险提醒：如果这是你的主力笔记本，请先确认你有退路。**

具体来说：装第三方驱动要改开机配置（EFI）。改坏了可能开不了机。所以：

- 先把 EFI 文件夹**整个复制一份备份**，放到你能找到的地方
- 确认你有一个**不依赖这块硬盘的 USB 启动盘**
- 别在系统正跑着的时候装卸驱动

作者也明确警告了：不要在运行中加载或卸载。

### 选项 C：用 OCLP 这个工具打补丁

**如果你有其他苹果电脑没支持的旧型号（比如老 Mac Pro），这是社区常用的办法。**

- 优点：通用，各种型号的苹果电脑都有成熟方案
- 缺点：需要**关闭系统的一部分安全保护**（SIP）
- 副作用：系统更新会把补丁撤销，得重来
- 代价：安全性降低

不推荐作为长期方案，但如果你没有别的选择，它确实有效。

### 选项 D：itlwm + HeliPort 组合

**如果你的安全顾虑大于对原生 Wi-Fi 的需求。**

- Wi-Fi 能用，但系统设置里的 Wi-Fi 开关用不了，要用一个额外软件（HeliPort）
- 好处：不需要关闭任何安全保护
- 代价：隔空投屏等功能没有

这个方案 macOS 15 上是**确定可用**的，不依赖任何第三方适配。

## 六、需要知道的几件事

**1. 你的网卡确实是 Intel 8265 吗**
如果不确定，可以在「关于本机 → 系统信息」里看"网络"那一栏。也可以直接查它的 PCI ID（8265 应该是 `0x24fd8086`，注意**不是** `0x27258086` —— 那是 AX200/AX210 的 ID，网上很多教程会搞混）：

```bash
ioreg -r -c IOPCIDevice -d 1 -l | grep -A12 '"model" = <"Intel Wireless 8265">' | grep '"IOName"'
# → "IOName" = "pci8086,24fd"
```

这个值以后会用到 —— 判断驱动认不认你的卡，看的就是它。

**2. 8265 在 macOS 15 上没有官方支持**
这是苹果的决定，不是 bug。你的网卡本身没坏，在 macOS 14 上照样用。

**3. macOS 15 已经不算新了**
截至现在，macOS 16 已经发布了。所以你问的是"能不能从 15 升到 16"，答案是**这个第三方版本只支持 15.8，16 不行**。

如果你的目标是"用最新的系统"，那这几个方案都不解决问题，只能继续留在 14。

**4. 第三方驱动的普遍风险**
这类项目个人维护，随时可能停止更新。作者今天在，明天可能就不管了。出问题也没人负责。

装任何这类东西之前，心里要有这个准备。

**你的 8265 在 macOS 15 上能用 —— 本机实测已经做到"扫得到、连得上、能上网"。** 真正稳的选择仍然是留在 macOS 14（下面第 5 点说的坑一个都没测过）。

想折腾的话，先查版本号、先备份 EFI、先准备 USB 恢复盘。完整的技术记录在 [`sequoia-8265-port.md`](sequoia-8265-port.md)。
